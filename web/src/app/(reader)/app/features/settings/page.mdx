# Settings

![ClauDepot — settings tab](/screenshots/settings.png)

ClauDepot's preference surface and the operational controls that
don't belong to any single tab. Sixteen sub-panes, grouped into
*Core* (everyday prefs) and *Advanced* (less-touched, ending at
About).

## General

Default section on launch, primary-account binding for the
top-level keyboard shortcuts (⌘1..⌘8 jump to a section), and the
small ergonomic toggles that don't deserve their own pane.

### Claude Code model settings

A second group in General edits Claude Code's own behaviour rather
than ClauDepot's. Every control here writes the user layer only —
`~/.claude/settings.json` (or the one under `CLAUDE_CONFIG_DIR`) —
so it applies to every account that uses that config. Project,
local and managed settings files are never written. Each change is
a read-modify-write through the one settings-file boundary, which
keeps every key it doesn't touch and refuses to overwrite a file it
can't parse.

- **Extended thinking by default** — `alwaysThinkingEnabled`.
  Claude Code's default is on and is represented by the key being
  absent, so *on* removes the key and *off* writes `false`; ClauDepot
  never writes `true`. When `MAX_THINKING_TOKENS` is set in the
  environment it decides instead, and the toggle is disabled with a
  note saying so. Affects new sessions; per-session flags still win.
- **Fast mode** — `fastMode`. The default is off, by absence, so *on*
  writes `true` and *off* removes the key. Fast mode runs the
  supported Opus models faster at $10 / $50 per million tokens and
  bills to usage credits, not the plan's included usage — the pane
  says so. `CLAUDE_CODE_DISABLE_FAST_MODE` overrides it and disables
  the toggle. A second switch, **Require per-session opt-in**, sets
  `fastModePerSessionOptIn`: every new session starts with fast mode
  off until `/fast` re-arms it. Usage credits on the account, and an
  owner's opt-in on Team and Enterprise, are also required and are
  not visible from disk, so a toggle reading *on* can still be
  refused by Claude Code at run time.
- **Selectable models** — `availableModels`, an ordered allowlist of
  family aliases (`opus`), version prefixes or full model ids, plus
  `enforceAvailableModels` (**Apply the list to the Default model**).
  Without enforcement, picking *Default* in `/model` bypasses the
  list; with it, Default becomes the first entry, so order matters
  and the list is never re-sorted. Clearing the list removes the key
  rather than writing `[]` — Claude Code reads an empty list as
  "only Default" — and enforcement is only written beside a non-empty list. It
  needs Claude Code 2.1.175 or later, and is reported as ignored when
  a managed policy file is present. Managed-only `availableModelsMatch`
  and `deniedModels` are shown when an administrator sets them, never
  written.
- **Commit & PR attribution** — `attribution` and the deprecated
  `includeCoAuthoredBy`, changed together in one write. *Default*
  removes the commit and PR texts; *Off* writes empty texts and
  `includeCoAuthoredBy: false`; *Custom* writes your own commit
  trailer and PR text. Other keys inside `attribution`, such as
  `sessionUrl`, are left as they are.

## Appearance

Theme — light / dark / system. Density (paper-mono compact / cosy).
Flipping `data-theme` on `<html>` switches without reloading.

## Notifications

OS-banner toggles per event class (automation completed, automation
failed, account verification expired, **rotation suggested**,
session waiting on you). Quiet hours, click-to-action defaults. The
bell-icon popover in the WindowChrome shows the last 500 dispatched
entries; corrupt log files are moved aside and the log starts fresh
— never fatal at boot.

## Network

The Status-bar dot at the bottom of the window. Toggles for
status-page polling (Anthropic + Resend + GitHub) and on-focus
latency probes. Cadence and backoff are tuned to be unobtrusive on
metered connections.

## Remote

The LAN appliance — the surface your phone talks to. Start and stop
the server, set the admin password, choose the bind address, and
revoke a paired device.

Three states, not two. `enabled` is a saved preference and survives
a crash, so *enabled but nothing is serving* is a real state and the
pane names it — a phone cannot reach a Mac whose preference merely
says yes. A server started from a terminal shows as serving too, and
the pane says so rather than offering a Stop it cannot honour.

The server runs inside ClauDepot, so **quitting stops it**. That is
deliberate: approving a tool call from your phone is armed only
while the surface is up, and a background daemon would make that
capability permanent.

Binding to every interface is accepted and never silent — if the
host ever gets a public address, the admin password is the only
thing between the internet and code execution as you.

**Quick prompts** live at the bottom of this pane. They are the
tappable chips above the remote panel's composer — a short name and
the longer text it sends — and they mean nothing outside that
surface, so they sit with it rather than in a pane of their own.

## Rotation

The marquee 0.1.22 feature. Author rules that swap the active CLI
account when an Anthropic-reported usage window crosses a threshold.

A rule is built from:

- **Trigger** — which window (`5h` / `7d` / `7d-Opus` / `7d-Sonnet`)
  and which percent. Triggers fire from the existing
  `/api/oauth/usage` poll, so there's no new network cost.
- **Selector** — `least-used` (lowest utilization in your candidate
  list), `round-robin`, or `explicit` (a fixed target).
- **Mode** — *Confirm* (default) raises a toast with a Switch
  action; *Auto* swaps immediately. Promote to Auto after watching a
  rule fire correctly.
- **Guards** — `min_interval_secs` (default 60s),
  `max_swaps_per_window` (default 3 per `resets_at` cycle), and
  `skip_when_cc_running` (defers cleanly without re-logging every
  tick).

Every swap attempt — applied, suggested, skipped, failed — lands in
a 500-entry ring-buffer audit log
(`~/.claudepot/rotation-audit.json`) visible in the same pane with
an outcome filter. Suggestions raised while the renderer was
disconnected (between reloads, before mount) are re-surfaced on
mount, so a Switch action is never silently lost.

The rule file (`~/.claudepot/rotation-rules.json`) is hand-edit-
friendly JSON with a stable `schema_version` field. The pure-Rust
evaluator in `claudepot-core::rotation::eval` is fully unit-tested,
including cycle-boundary regressions. See
[`dev-docs/auto-rotation.md`](https://github.com/xiaolai/claudepot-app/blob/main/dev-docs/auto-rotation.md)
for the design.

## Relay

Lets Claude Code on your other tailnet machines use an account
registered here, with no login on those machines. Publish an
account, start the relay, then pair a machine with a short-lived
code; that machine gets a device token that reaches inference and
nothing else. The account Claude Code is using on this Mac is never
offered.

Like Remote, the relay runs inside ClauDepot, so **quitting stops
it**. It always serves TLS. Each paired device shows when it was last
seen and an estimate of today's spend.

**Revoke cuts a device off at once**, open streams included. A relay started from a terminal
(`claudepot relay serve`) shows as serving, and the pane locks its
other controls rather than editing state under it. On macOS and
Linux, Revoke still works there, because it reaches the running
relay; the reverse holds too, so `claudepot relay revoke` in a
terminal reaches a relay serving in the window. On Windows, or when
the running relay can't be reached, Revoke is disabled and says to
stop that relay first.

## Retention

Claude Code deletes your saved conversations. Not once — on **every
launch**, anything older than thirty days. It counts exactly what it
removed, then throws the number away, and nothing anywhere in its
interface mentions the setting that controls it.

This pane is the only place you find out.

It opens with the consequence on *your* machine, not the policy:

> **Retention — 30 days**, Claude Code's default, not a choice you made
> 1,247 transcripts will be deleted the next time Claude Code starts.
> Oldest surviving conversation: 2026-06-06.

Pick a longer window — 90 days, a year, ten years — and that line goes
quiet on its own.

**Why the folder size never warned you.** Cleanup removes the small,
valuable session transcripts and never touches the nested subagent
files underneath them. Those are the bulk. So the directory keeps
growing while the conversations inside it disappear, and no amount of
watching disk usage would ever have told you.

**Zero is not "off".** It is the most destructive value the setting
has: *write no transcripts at all, and delete the existing ones at
startup*. So it isn't on the duration scale. Reaching it takes a
separate, clearly-labelled action behind a type-to-confirm prompt,
worded as what it does rather than what it disables.

**A longer window buys time; it is not a backup.** Those files still
live in Claude Code's cache directory under Claude Code's rules. If
what you want is a durable archive, that is
[`claudepot corpus`](/app/features/memory).

## Health

A single pane that consolidates the warning channels scattered
across older builds: keychain reachability, account-verification
freshness, Claude Code daemon state, and the `cc_doctor` probe
output. The same signals that surface as toasts and the
StatusIssuesBanner have a quiet home here, so an operator who
dismissed a banner can still see what triggered it.

## MCP

One-click installer for the ClauDepot Memory MCP server (the one
that exposes `claudepot_search_memory` and friends &mdash; see the
[Memory tab](/app/features/memory)). User/project scope toggle that
mirrors the `/init-workspace` convention: *user* writes to
`~/.claude/AGENTS.md`, *project* writes to `./AGENTS.md` for the
currently-active project. Snippet is shown verbatim before install
so nothing is silently appended.

CLI equivalents:

```bash
claudepot mcp print-snippet    # show, don't install
claudepot mcp install-snippet  # narrow-edit the right AGENTS.md
```

## Cleanup

The disk-reclaim tools that keep `~/.claude/` from quietly growing
to many gigabytes. Three operations:

### Prune

Removes orphaned session files — transcripts whose project
directory no longer exists. Lists them first so you can review.

```bash
claudepot session prune --dry-run
claudepot session prune
```

### Slim

Reduces transcript size without losing the conversation history.
Canonical use is `--strip-images`, which drops bulky image payloads
that CC stored verbatim in `toolUseResult` (display-only) while
leaving the same images in `message.content` (where Claude already
transformed them for token-counting). Saved on average ~40% per
transcript with images.

```bash
claudepot session slim --strip-images <session-id>
claudepot session slim --strip-images --all
```

### Trash

A 7-day soft-delete bin. Anything you remove via Cleanup lands here
first; after 7 days it's permanently deleted. Restore or empty
manually any time.

```bash
claudepot trash list
claudepot trash restore <id>
claudepot trash empty
```

A *Rebuild index* button alongside re-parses every session file
from scratch when the SQLite session cache drifts from on-disk
truth. Same operation as `claudepot session rebuild-index`.

The Cleanup pane also hosts an **Artifacts** sub-view: disabled
ClauDepot artifacts (rules, sections, integrations a future build
turned off) and their own trash list.

## Protected paths

Project paths whose *sibling state* survives an orphan clean. When
cleaning removes an orphaned project, it normally deletes the
artifact folder under `~/.claude/projects/` **and** strips that
path's entry from the `~/.claude.json` projects map and its lines
from `~/.claude/history.jsonl`. For a protected path the artifact
folder is still removed — it sits inside Claude Code's own area —
but the `~/.claude.json` entry and the history lines are left alone,
and the clean reports how many orphans that applied to. It is not a
write fence: nothing else in ClauDepot consults this list.

Matching is exact, not by prefix: protecting `/Users` covers a
project whose path is exactly `/Users`, not the projects beneath it.
That is the case the defaults exist for — a session started in `/`,
`~`, `/Users`, `/tmp` and similar (`C:\`, `C:\Users`, … on Windows),
where stripping the entry would wipe config you almost certainly
want to keep.

Defaults are built in; the store
(`~/.claudepot/protected-paths.json`) records only your additions and
the defaults you removed, so a default added by a later release
reaches you automatically. *Reset to defaults* deletes the store. If
the file can't be read, cleaning falls back to the built-in defaults,
never to no protection. The pane accepts absolute and `~`-prefixed
paths, and refuses relative paths, `..` segments and bare filesystem
or drive roots.

## GitHub

A single Personal Access Token slot for ClauDepot's own GitHub
calls (release manifest fetch for the auto-updater, mostly).
Stored in the OS keychain, zeroized from local memory on every IPC
exit path. Per-route GitHub credentials live in the
[Keys tab](/app/features/keys), not here.

## Locks

Force-breaks a lock file left behind by a crashed project rename.
Each rename holds one lock, keyed on the source project's sanitized
path, at `~/.claudepot/repair/locks/<slug>.lock`; it records the
holder's PID, hostname and start time. (Orphan cleaning, project
removal and import take locks in the same directory.)

Most stale locks never reach this pane: the next operation breaks
one itself when the holder is gone (a rename also writes an audit
record of the lock it broke; the other operations only log it) — on the
same host, when its PID is dead (by age on Windows); on another
host, when the lock is older than 24 hours
(`CLAUDEPOT_LOCK_STALE_HOURS` overrides). The pane is for the lock
that check refuses to break.

Enter the project's path — the rename's source — or its sanitized
folder name; the lock is found from that, and a name that could
escape the locks directory is refused. *Break lock* then deletes it
**without checking whether the holder is still alive**, so break
one only when no rename is running. The prior holder is written to
`~/.claudepot/repair/journals/broken-lock-<timestamp>.json` and named
in the confirmation toast. The same action, behind a confirmation,
sits on each pending rename in Projects → Maintenance; the CLI is
`claudepot project repair --break-lock <path>`, which asks for `-y`.

## Diagnostics

The `claudepot doctor` flow as a button: probe the keychain, probe
each registered account, probe the data directory, probe Claude
Code's own state. Output is structured and copyable for bug
reports. CLI mirror: `claudepot doctor`.

## About

Version, channel, license, and a link to the auto-updater. ClauDepot's
own updates flow through here — *not* through Global → Updates,
which manages Claude Code and Claude Desktop versions.

## What's on disk

For reference, the data directories ClauDepot manages:

- `~/.claude/projects/<slug>/*.jsonl` — Claude's session
  transcripts. Owned by Claude; ClauDepot reads and (carefully)
  rewrites.
- `~/.claudepot/accounts.db` — accounts + verification state.
  ClauDepot-owned, single-writer.
- `~/.claudepot/sessions.db` — session-index cache. Re-parse guard
  is `(size, mtime_ns)` per file_path. Rebuild any time via
  *Cleanup → Rebuild index*.
- `~/.claudepot/notifications.json` — ring buffer of dispatched
  toasts and OS banners (≤ 500 entries).
- `~/.claudepot/rotation-rules.json` — user-authored auto-rotation
  rules. Hand-edit-friendly JSON.
- `~/.claudepot/rotation-audit.json` — ring buffer of rotation
  outcomes (≤ 500 entries) shown in the Rotation pane.
- `~/.claudepot/usage-snapshot.json` — per-account utilization
  written every 5 min (mode `0600`). Cron jobs and CC Bash
  subprocesses can consult per-account usage without going through
  the keychain. `written_at` is the consumer's tripwire — older
  than 5 min means ClauDepot isn't running, treat as historical.

`CLAUDEPOT_DATA_DIR` overrides the `~/.claudepot/` paths.
