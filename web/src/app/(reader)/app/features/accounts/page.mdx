# Accounts

![ClauDepot — accounts tab](/screenshots/accounts.png)

The Accounts tab is the home base. Each row is a registered Anthropic
identity — an email address Claude knows you by. ClauDepot remembers
the credentials in your OS keychain (separate from Claude&rsquo;s own)
and lets you switch between them without editing files in `~/.claude/`.

## Two independent slots

Claude Code reads credentials from one slot. Claude Desktop reads
session files from a different slot. **They are independent.** You can
have:

- Account A active in CLI, Account B active in Desktop.
- The same account active in both.
- Either slot empty while the other is active.

The header on each account card shows which slots it currently owns.

## Add an account

Three paths in:

- **From current Claude Code session.** If you&rsquo;ve `claude /login`-ed
  on this machine, ClauDepot finds the credentials and offers to
  register them as a named account.
- **Browser login.** Spawns the Claude OAuth flow in your default
  browser; the resulting credentials are stored under the email you
  authenticate with.
- **Paste an existing OAuth token.** For accounts already provisioned
  on another machine.

Identity is the email address. Email prefix matching means you can type
just `joe` and ClauDepot resolves it as long as exactly one registered
account starts with that prefix.

## Switch slots

Each account card has a *Use for CLI* and *Use for Desktop* button.
Click either to make that account the active slot. Switching is
atomic: it writes the credentials, signals Claude to refresh, and
verifies the change took effect before reporting success.

## Verify

The shield icon next to each account runs a verification check —
calls the Anthropic API with the stored credentials and confirms the
token is still valid. Useful before committing to a long task.

The *Verify all* button at the top runs the check across every
registered account in parallel.

## Keeping stored accounts signed in

A Claude Code access token lasts about eight hours. Claude Code keeps
the token of the account it is signed in as fresh by itself, but the
accounts ClauDepot holds in reserve have nobody doing that, so they
used to read *Expired* everywhere a live token is needed — usage
windows, the Activities strip, the tray — until you verified or
switched to them.

While the desktop app is open, ClauDepot now renews them in the
background. Every five minutes it picks **at most one** stored account
whose access token has expired and runs the same verification as the
shield icon; when the server rejects the expired token, that check
spends the account&rsquo;s refresh token (the long-lived credential
that mints new access tokens) and saves the new one. Accounts take
turns, so one that keeps failing does not block the others.

What it leaves alone:

- **The account Claude Code is using.** That token belongs to Claude
  Code; ClauDepot never refreshes it.
- **Accounts already known to be bad** — signed out, refresh token
  rejected, or holding a different email than the one registered
  (*drift*). Only signing in again fixes those, so it stops retrying.
- **Tokens that have not expired yet.**

A refresh renews the access token, not the login. The login itself
ends on a fixed date, about 30 days after you signed in, shown on the
account card as *login ends …*; after that, sign in again in the
browser. Claude Desktop sessions are not part of this. There is no
setting to turn it off, and the `claudepot` CLI does not run it.

## Rate limits at a glance

Each account card surfaces Anthropic&rsquo;s reported utilization
windows alongside identity: `5h`, `7d` (all-models), and `7d` Sonnet.
Updated by a 5-minute background poll &mdash; same snapshot the
[auto-rotation rules](/app/features/settings#rotation) read &mdash;
so picking which account to bind for the next hour&rsquo;s work
doesn&rsquo;t require leaving ClauDepot for the Anthropic dashboard.

If you cross a threshold often, **Settings &rarr; Rotation** lets
you turn the manual swap into a rule: "when 5h on this account
crosses 80%, swap to my least-used alternate." Confirm-mode raises a
toast with a Switch action; auto-mode swaps immediately, audited.

## Remove

Removing an account purges the keychain entry and the local DB row.
Claude&rsquo;s own session files are untouched — if the account is
currently active in a slot, ClauDepot detaches first, then deletes.

## Where ClauDepot finds Claude Desktop

The Desktop slot works by reading and swapping the files in Claude
Desktop&rsquo;s data folder, which starts with its `config.json`:

- **macOS:** `~/Library/Application Support/Claude`.
- **Windows:** Desktop is an MSIX app (Windows&rsquo; packaged-app
  format), and recent versions move their data out of the package.
  Before the move it is in
  `%LOCALAPPDATA%\Packages\<package family>\LocalCache\Roaming\Claude`;
  after it, in `%LOCALAPPDATA%\Claude-Data\<package family, lowercase>`,
  with a `.user-data-left.…` marker file left in the old folder.
  ClauDepot follows Desktop to the new folder from 0.7.1; earlier
  versions only looked in the old one. It never looks there when
  `%LOCALAPPDATA%` is on a network share, because Desktop does not move
  in that case either.
- **Linux:** there is no Claude Desktop slot.

If `config.json` is not in the folder ClauDepot checked, the error
names that folder: *Either Desktop hasn&rsquo;t been launched yet, or it
keeps its data somewhere Claudepot doesn&rsquo;t look.* If Desktop is
open and signed in when you see this, compare the folder in the message
with where your Desktop data actually is. A few rarer Windows layouts,
such as a fallback folder under `%APPDATA%\Claude`, are not followed.

## Architecture

Account state is in `~/.claudepot/accounts.db` (SQLite, single-writer).
Credentials live in the OS keychain under the bundle ID
`com.claudepot.app`. ClauDepot uses two distinct keychain surfaces
on macOS — one for its own secrets via the `keyring` crate, one to
read Claude&rsquo;s credential via `/usr/bin/security` subprocess.
See the
[architecture rules](https://github.com/xiaolai/claudepot-app/blob/main/.claude/rules/architecture.md)
for why this split matters.
